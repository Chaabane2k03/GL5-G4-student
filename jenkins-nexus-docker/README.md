# Jenkins, SonarQube, and Nexus

This folder contains two independent Compose projects:

- `docker-compose.nexus.yml` starts Nexus Repository Manager.
- `docker-compose.jenkins.yml` starts Jenkins and the SonarQube webhook helper.

Jenkins and Nexus communicate through the external Docker network
`gl5-jenkins-nexus`. Nexus data is persisted in the external volume
`gl5-jenkins_nexus-data`.

The Jenkins jobs are grouped under the `service-pipelines` Jenkins folder.
Each multibranch job scans only `main`, `develop`, and `feature/jenkins-nexus`,
and publishes Maven artifacts to:

- `gl5-student-snapshots`
- `gl5-student-releases`

## Prerequisites

- Docker Desktop with Compose v2.
- The repository cloned locally.
- Ports `8081`, `8092`, `50000`, and `9000` available.
- At least 4 GB of memory available to Docker.

All commands below are PowerShell commands executed from this folder:

```powershell
Set-Location D:\Raed\Desktop\GL5-G4-student\jenkins-nexus-docker
```

## 1. Configure environment variables

Create the local environment file. Do not commit this file because it contains
credentials and tokens:

```powershell
Copy-Item .env.example .env
notepad .env
```

Set these values in `.env`:

```dotenv
JENKINS_ADMIN_USER=admin
JENKINS_ADMIN_PASSWORD=change-this-password
JENKINS_PORT=8092
JENKINS_EXTERNAL_URL=http://localhost:8092/
SONAR_TOKEN=<SonarQube-token>
NEXUS_PORT=8081
NEXUS_USER=admin
NEXUS_PASSWORD=<Nexus-password>
```

`NEXUS_PASSWORD` must be the password Jenkins will use when publishing
artifacts. It is not necessarily the initial password generated by Nexus; it is
the current password of the Nexus user in `NEXUS_USER`.

## 2. Start SonarQube

From the repository root, start the shared SonarQube stack:

```powershell
Set-Location D:\Raed\Desktop\GL5-G4-student
docker compose -f docker-compose.sonar.yml up -d
```

Wait until SonarQube is ready:

```powershell
Invoke-WebRequest http://localhost:9000/api/system/status
```

The response should contain a status of `UP`. Create a SonarQube user token in
**My Account → Security**, then put it in `jenkins-nexus-docker/.env` as
`SONAR_TOKEN`.

## 3. Create the shared Jenkins/Nexus network

Create this network once. If it already exists, Docker reports that it exists;
that is safe:

```powershell
docker network create gl5-jenkins-nexus
```

The SonarQube Compose project creates the separate external network
`gl5-sonar-net`, which Jenkins uses for SonarQube analysis and webhooks.

## 4. Start Nexus

Start Nexus independently from Jenkins:

```powershell
Set-Location D:\Raed\Desktop\GL5-G4-student\jenkins-nexus-docker
docker compose -f docker-compose.nexus.yml up -d
docker compose -f docker-compose.nexus.yml ps
```

Open Nexus at <http://localhost:8081>. On a new Nexus volume, retrieve the
generated administrator password:

```powershell
docker exec nexus-igl5 cat /nexus-data/admin.password
```

Sign in with username `admin` and that generated password. Complete the initial
setup, then change the administrator password to the value you put in
`NEXUS_PASSWORD`.

If Nexus was already initialized, `admin.password` may no longer exist. Use the
current Nexus administrator password instead.

## 5. Create the Maven repositories

### Option A: Nexus web interface

In Nexus:

1. Select **Server administration and configuration**.
2. Select **Repositories**.
3. Click **Create repository**.
4. Choose **maven2 (hosted)**.
5. Create the snapshot repository with:
   - **Name:** `gl5-student-snapshots`
   - **Version policy:** `Snapshot`
   - **Layout policy:** `Strict`
   - **Deployment policy:** `Allow redeploy`
   - **Blob store:** `default`
6. Create the release repository with:
   - **Name:** `gl5-student-releases`
   - **Version policy:** `Release`
   - **Layout policy:** `Strict`
   - **Deployment policy:** `Disable redeploy`
   - **Blob store:** `default`

The repository names must match the service `ci.env` files exactly.`

Verify the repository endpoints:

```powershell
Invoke-WebRequest http://localhost:8081/repository/gl5-student-snapshots/
Invoke-WebRequest http://localhost:8081/repository/gl5-student-releases/
```

An HTTP `401` or `403` means authentication is required or the user lacks
permission. An HTTP `200`, `404`, or repository-specific response confirms that
the Nexus server is reachable; the repository must also appear in the Nexus
repository list.

## 6. Start Jenkins

Start Jenkins after Nexus is running:

```powershell
docker compose -f docker-compose.jenkins.yml up -d --build
docker compose -f docker-compose.jenkins.yml ps
```

Open Jenkins at <http://localhost:8092> and sign in with
`JENKINS_ADMIN_USER` and `JENKINS_ADMIN_PASSWORD`.

The Jenkins CasC configuration creates the global credentials:

- `sonar-token`, from `SONAR_TOKEN`
- `nexus`, from `NEXUS_USER` and `NEXUS_PASSWORD`

If you change either credential in `.env`, recreate Jenkins:

```powershell
docker compose -f docker-compose.jenkins.yml up -d --force-recreate jenkins
```

The six multibranch jobs (`config-server`, `department-service`,
`enrollment-service`, `student-service`, `course-service`, and `api-gateway`)
are created inside the `service-pipelines` folder from [`casc.yaml`](./casc.yaml).
Each multibranch job also scans the repository automatically every 24 hours.
To scan immediately, open a multibranch job and select **Scan Multibranch
Pipeline Now** from its menu.

## 7. Register the SonarQube webhook

Run the helper once after Jenkins and SonarQube are running:

```powershell
docker compose -f docker-compose.jenkins.yml run --rm sonar-webhook-init
```

The command should finish with `Registered webhook ...` or
`Webhook ... already registered.`.

## 8. Verify the complete setup

Check all services:

```powershell
docker compose -f docker-compose.nexus.yml ps
docker compose -f docker-compose.jenkins.yml ps
docker ps --filter "name=gl5-sonarqube"
```

Check that Jenkins can resolve and reach Nexus:

```powershell
docker exec gl5-jenkins sh -c "getent hosts nexus-igl5"
docker exec gl5-jenkins sh -c "curl -fsS http://nexus-igl5:8081/service/rest/v1/status"
```

The Nexus response should report a healthy status. Then open the
`service-pipelines` folder, select a branch under one of the multibranch jobs,
and run it with **Build Now**. The Maven publish stage should use URLs such as:

```text
http://nexus-igl5:8081/repository/gl5-student-snapshots/
```

## 9. Stop, restart, and reset

To completely reset Jenkins and Nexus and rebuild both containers from scratch,
run the following destructive sequence. It deletes all Jenkins jobs/builds,
credentials, Maven cache, Nexus repositories, and Nexus artifacts:

```powershell
docker compose -f docker-compose.jenkins.yml down
docker compose -f docker-compose.nexus.yml down
docker volume rm gl5-jenkins_jenkins-home gl5-jenkins_maven-repo gl5-jenkins_nexus-data
docker volume create gl5-jenkins_nexus-data
docker compose -f docker-compose.nexus.yml up -d
docker compose -f docker-compose.jenkins.yml up -d --build
```

After Nexus initializes, recreate the two Maven repositories by following
[step 5](#5-create-the-maven-repositories), then run the webhook helper.

Stop Jenkins without stopping Nexus:

```powershell
docker compose -f docker-compose.jenkins.yml down
```

Stop Nexus without stopping Jenkins:

```powershell
docker compose -f docker-compose.nexus.yml down
```

Start either service again with its corresponding `up -d` command.

To erase Nexus repositories and artifacts, stop Nexus and remove its persistent
volume. This is destructive:

```powershell
docker compose -f docker-compose.nexus.yml down
docker volume rm gl5-jenkins_nexus-data
```

Do not use `docker compose down -v` unless you also intend to delete the Jenkins
home and Maven cache volumes for that Compose project.
