# Jenkins, SonarQube, and Nexus

This folder contains two independent Compose projects:

- `docker-compose.nexus.yml` starts Nexus Repository Manager.
- `docker-compose.jenkins.yml` starts Jenkins and the SonarQube webhook helper.

Jenkins and Nexus communicate through the external Docker network
`gl5-jenkins-nexus`. Nexus data is persisted in the external volume
`gl5-jenkins_nexus-data`.

The Jenkins jobs are grouped under the `service-pipelines` Jenkins folder.
Each multibranch job scans only `main`, `develop`, and `feature/jenkins-nexus`,
is triggered by GitHub push webhooks sent to the public Jenkins URL, and
publishes Maven artifacts to:

- `gl5-student-snapshots`
- `gl5-student-releases`

## Prerequisites

- Docker Desktop with Compose v2.
- The repository cloned locally.
- Ports `8081`, `8092`, `50000`, and `9000` available.
- At least 4 GB of memory available to Docker.

All commands below are PowerShell commands executed from this folder:

```powershell
Set-Location D:\Raed\Desktop\GL5-G4-student\jenkins-nexus-docker
```

## 1. Configure environment variables

Create the local environment file. Do not commit this file because it contains
credentials and tokens:

```powershell
Copy-Item .env.example .env
notepad .env
```

Set these values in `.env`:

```dotenv
JENKINS_ADMIN_USER=admin
JENKINS_ADMIN_PASSWORD=change-this-password
JENKINS_PORT=8092
JENKINS_EXTERNAL_URL=https://raedbettaher.chaabaneboussadia.dev/
GITHUB_USER=Chaabane2k03
GITHUB_TOKEN=<GitHub-personal-access-token>
PER_SERVICE_JOBS=true
SONAR_TOKEN=<SonarQube-token>
NEXUS_PORT=8081
NEXUS_USER=admin
NEXUS_PASSWORD=<Nexus-password>
```

`NEXUS_PASSWORD` must be the password Jenkins will use when publishing
artifacts. It is not necessarily the initial password generated by Nexus; it is
the current password of the Nexus user in `NEXUS_USER`.

`JENKINS_EXTERNAL_URL` is the URL Jenkins advertises to the outside world. It
must be the public URL that GitHub and SonarQube can reach, with a trailing
slash, because Jenkins builds its webhook endpoints from it:

- `https://raedbettaher.chaabaneboussadia.dev/github-webhook/`
- `https://raedbettaher.chaabaneboussadia.dev/sonarqube-webhook/`

If you only work locally, you can set it to `http://localhost:8092/` instead;
GitHub will then not be able to deliver webhooks.

`GITHUB_TOKEN` is optional. Leave it empty to scan GitHub anonymously (public
repositories only, heavily rate limited). [Step 7](#7-configure-the-github-credential-and-webhook)
explains how to create it.

## 3. Create the shared Jenkins/Nexus network

Create this network once. If it already exists, Docker reports that it exists;
that is safe:

```powershell
docker network create gl5-jenkins-nexus
```

The SonarQube Compose project creates the separate external network
`gl5-sonar-net`, which Jenkins uses for SonarQube analysis and webhooks.

## 4. Start Nexus

Start Nexus independently from Jenkins:

```powershell
Set-Location D:\Raed\Desktop\GL5-G4-student\jenkins-nexus-docker
docker compose -f docker-compose.nexus.yml up -d
docker compose -f docker-compose.nexus.yml ps
```

Open Nexus at <http://localhost:8081>. On a new Nexus volume, retrieve the
generated administrator password:

```powershell
docker exec nexus-igl5 cat /nexus-data/admin.password
```

Sign in with username `admin` and that generated password. Complete the initial
setup, then change the administrator password to the value you put in
`NEXUS_PASSWORD`.

If Nexus was already initialized, `admin.password` may no longer exist. Use the
current Nexus administrator password instead.

## 5. Create the Maven repositories

### Option A: Nexus web interface

In Nexus:

1. Select **Server administration and configuration**.
2. Select **Repositories**.
3. Click **Create repository**.
4. Choose **maven2 (hosted)**.
5. Create the snapshot repository with:
   - **Name:** `gl5-student-snapshots`
   - **Version policy:** `Snapshot`
   - **Layout policy:** `Strict`
   - **Deployment policy:** `Allow redeploy`
   - **Blob store:** `default`
6. Create the release repository with:
   - **Name:** `gl5-student-releases`
   - **Version policy:** `Release`
   - **Layout policy:** `Strict`
   - **Deployment policy:** `Disable redeploy`
   - **Blob store:** `default`

The repository names must match the service `ci.env` files exactly.`

Verify the repository endpoints:

```powershell
Invoke-WebRequest http://localhost:8081/repository/gl5-student-snapshots/
Invoke-WebRequest http://localhost:8081/repository/gl5-student-releases/
```

An HTTP `401` or `403` means authentication is required or the user lacks
permission. An HTTP `200`, `404`, or repository-specific response confirms that
the Nexus server is reachable; the repository must also appear in the Nexus
repository list.

## 6. Start Jenkins

Start Jenkins after Nexus is running:

```powershell
docker compose -f docker-compose.jenkins.yml up -d --build
docker compose -f docker-compose.jenkins.yml ps
```

Open Jenkins at <http://localhost:8092> and sign in with
`JENKINS_ADMIN_USER` and `JENKINS_ADMIN_PASSWORD`.

The Jenkins CasC configuration creates the global credentials:

- `sonar-token`, from `SONAR_TOKEN`
- `nexus`, from `NEXUS_USER` and `NEXUS_PASSWORD`
- `github-token`, from `GITHUB_USER` and `GITHUB_TOKEN` (see
  [step 7](#7-configure-the-github-credential-and-webhook))

If you change any of these credentials in `.env`, recreate Jenkins:

```powershell
docker compose -f docker-compose.jenkins.yml up -d --force-recreate jenkins
```

Jenkins is reachable at <http://localhost:8092> and, through Cloudflare, at
<https://raedbettaher.chaabaneboussadia.dev/>.

The multibranch jobs are created inside the `service-pipelines` folder from
[`casc.yaml`](./casc.yaml). Every job points at the `Chaabane2k03/GL5-G4-student`
repository and only builds the `main`, `develop`, and `feature/jenkins-nexus`
branches. Each multibranch job scans the repository automatically every 24
hours; to scan immediately, open it and select **Scan Multibranch Pipeline Now**.

Two job layouts are available:

- `all-services` runs the root [`Jenkinsfile`](../Jenkinsfile): one pipeline that
  builds only the services touched by a push, in parallel, with tests, SonarQube
  quality gate, container image and Nexus publishing. This is the recommended
  layout; see [PIPELINE.md](../PIPELINE.md).
- `department-service`, `enrollment-service`, `student-service`,
  `course-service`, and `api-gateway` run the per-service Jenkinsfile of each
  folder.

Both are created by default, so a push can build twice. Once `all-services` is
trusted, set this in `.env` and recreate Jenkins:

```dotenv
PER_SERVICE_JOBS=false
```

## 7. Configure the GitHub credential and webhook

The multibranch jobs use the GitHub branch source, so Jenkins needs a GitHub
token and GitHub must be able to notify Jenkins about pushes.

### 7.1 Create a personal access token

In GitHub, open **Settings → Developer settings → Personal access tokens** and
choose one of the two options below.

**Classic token (simplest):**

1. Select **Tokens (classic) → Generate new token (classic)**.
2. Give it a note such as `jenkins-gl5` and an expiration date.
3. Select the `repo` scope. Without it Jenkins cannot read the repository or
   its branches.
4. Select `admin:repo_hook` only if you later want Jenkins to create and update
   hooks by itself. This guide registers the webhook manually, so it is not
   required.
5. Click **Generate token** and copy the value that starts with `ghp_`. GitHub
   shows it only once.

**Fine-grained token (least privilege):**

1. Select **Fine-grained tokens → Generate new token**.
2. Set **Repository access** to **Only select repositories** and pick
   `GL5-G4-student`.
3. Under **Permissions → Repository permissions** set:
   - **Contents:** Read-only
   - **Metadata:** Read-only (selected automatically)
   - **Pull requests:** Read-only (optional, only if you want pull request
     branches to be discovered)
   - **Commit statuses:** Read and write (optional, only if you want Jenkins
     to report build status on commits)
4. Generate the token and copy it.

### 7.2 Put the token in `.env`

Edit `jenkins-nexus-docker/.env`:

```dotenv
GITHUB_USER=Chaabane2k03
GITHUB_TOKEN=ghp_your_token_here
```

`GITHUB_USER` is the account or organization that owns the repository. Both
values are read by [`casc.yaml`](./casc.yaml), which creates a global
**Username with password** credential with the ID `github-token`. The branch
source only attaches that credential when `GITHUB_TOKEN` is not empty.

Then recreate Jenkins so the credential is imported:

```powershell
docker compose -f docker-compose.jenkins.yml up -d --force-recreate jenkins
```

Verify it: **Manage Jenkins → Credentials → System → Global credentials** should
list `github-token` (`GitHub personal access token (GITHUB_TOKEN)`). Do not edit
that credential in the web UI; it is managed by CasC and will be overwritten on
the next restart. Change `.env` instead.

A typo in the token makes branch scanning fail with `Bad credentials` instead of
falling back to anonymous access. If scanning breaks right after adding the
token, check the Jenkins log:

```powershell
docker logs gl5-jenkins --tail 200
```

### 7.3 Add the webhook in GitHub

1. Open <https://github.com/Chaabane2k03/GL5-G4-student/settings/hooks>.
2. Click **Add webhook**.
3. Set **Payload URL** to:

   ```text
   https://raedbettaher.chaabaneboussadia.dev/github-webhook/
   ```

4. Set **Content type** to `application/json`.
5. Leave **Secret** empty. Jenkins is not configured with a hook secret here; if
   you add one in GitHub you must also configure the same secret in Jenkins,
   otherwise every delivery is rejected.
6. Keep **SSL verification** enabled.
7. Under **Which events would you like to trigger this webhook?** choose
   **Just the push event**. Add pull requests only if you want Jenkins to react
   to them as well.
8. Make sure **Active** is checked and click **Add webhook**.

Use the exact URL, including the trailing slash and without a port number: the
`github-webhook/` endpoint is what the GitHub plugin exposes, and it is derived
from `JENKINS_EXTERNAL_URL`. The multibranch jobs themselves have no per-job
hook trigger, so nothing else has to be configured in Jenkins.

If `JENKINS_EXTERNAL_URL` ever changes, update this webhook URL as well.

### 7.4 Cloudflare

Jenkins sits behind Cloudflare in front of port `8092`. Cloudflare must let
GitHub's `POST` requests reach `/github-webhook/`:

- Do not enable **Under Attack Mode** or a managed challenge on that path.
  A challenge answers `403`, so GitHub deliveries fail and builds never start.
- If the WAF or bot protection blocks the path, add a rule that skips those
  checks for requests whose URI path is `/github-webhook/`.
- Do not put Cloudflare Access in front of the webhook. GitHub cannot complete
  an interactive login.

### 7.5 Check that it works

1. In GitHub, open the webhook you just created and select the **Recent
   Deliveries** tab.
2. A push delivery should return `200` with a response body of `{}` or similar.
   A `403`, a `302` redirect to a login page, or a Cloudflare error page means
   the URL, Cloudflare rules, or `JENKINS_EXTERNAL_URL` are wrong.
3. You can also test the endpoint directly:

   ```powershell
   Invoke-WebRequest -Method Post -Uri https://raedbettaher.chaabaneboussadia.dev/github-webhook/ -ContentType application/json -Body '{}'
   ```

   `200` is expected. `403` means Cloudflare or a proxy is blocking the request.

4. Push a commit to `main`, `develop`, or `feature/jenkins-nexus`. Jenkins
   indexes the repository and starts the branch build for the affected service.
   The push event only triggers a scan; a build starts when the branch is
   discovered and its `Jenkinsfile` exists at the configured path.

### 7.6 If Jenkins still says "anonymous access"

A branch indexing log that contains this line used the anonymous API:

```text
Connecting to https://api.github.com with no credentials, anonymous access
```

The line is informational, not an error. Anonymous access only sees public
repositories and is limited to 60 requests per hour, so it is not suitable here.
When the credential is used, the same line instead reads:

```text
Connecting to https://api.github.com using <user>/****** (GitHub personal access token (GITHUB_TOKEN))
```

Work through these checks in order:

1. Confirm the container received the token. Compose reads `.env` only when it
   creates the container, so a token added afterwards needs a recreate:

   ```powershell
   docker exec gl5-jenkins sh -c 'test -n "$GITHUB_TOKEN" && echo SET || echo EMPTY'
   docker compose -f docker-compose.jenkins.yml up -d --force-recreate jenkins
   ```

   A `SET` result should be followed by a scan, not another recreate. If it says
   `EMPTY`, the variable is missing from `.env` or a shell variable of the same
   name is overriding it. Compose gives precedence to exported shell variables
   over `.env`; unset it with `Remove-Item Env:GITHUB_TOKEN` or open a fresh
   terminal.

2. Confirm each job references the credential:

   ```powershell
   docker exec gl5-jenkins find /var/jenkins_home/jobs/service-pipelines/jobs -name config.xml -exec grep -l github-token {} +
   ```

   This should list all five jobs. If it lists none, the container started
   before `casc.yaml` had the `credentialsId` block; recreate Jenkins.

3. Confirm the credential exists in **Manage Jenkins → Credentials → System →
   Global credentials** as `github-token`. Its username must be the account that
   owns the token (not the repository owner, unless they are the same).

4. Re-run a scan with **Scan Multibranch Pipeline Now** and read the new log.
   Old indexing logs keep the old message, so always look at the latest run.

5. If the log now reports `Bad credentials`, the token is wrong, expired, or
   lacks the `repo` scope. Generate a new token, update `.env`, and recreate
   Jenkins.

## 10. Stop, restart, and reset

To completely reset Jenkins and Nexus and rebuild both containers from scratch,
run the following destructive sequence. It deletes all Jenkins jobs/builds,
credentials, Maven cache, Nexus repositories, and Nexus artifacts:

```powershell
docker compose -f docker-compose.jenkins.yml down
docker compose -f docker-compose.nexus.yml down
docker volume rm gl5-jenkins_jenkins-home gl5-jenkins_maven-repo gl5-jenkins_nexus-data
docker volume create gl5-jenkins_nexus-data
docker compose -f docker-compose.nexus.yml up -d
docker compose -f docker-compose.jenkins.yml up -d --build
```

After Nexus initializes, recreate the two Maven repositories by following
[step 5](#5-create-the-maven-repositories), then run the webhook helper.

Stop Jenkins without stopping Nexus:

```powershell
docker compose -f docker-compose.jenkins.yml down
```

Stop Nexus without stopping Jenkins:

```powershell
docker compose -f docker-compose.nexus.yml down
```

Start either service again with its corresponding `up -d` command.

To erase Nexus repositories and artifacts, stop Nexus and remove its persistent
volume. This is destructive:

```powershell
docker compose -f docker-compose.nexus.yml down
docker volume rm gl5-jenkins_nexus-data
```

Do not use `docker compose down -v` unless you also intend to delete the Jenkins
home and Maven cache volumes for that Compose project.
